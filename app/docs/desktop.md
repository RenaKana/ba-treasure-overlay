# BA 寻宝助手

本地 Windows 概率叠加工具，支持 9×5 棋盘、三类可旋转矩形物品。保留上游求解器，按本轮卡片建立图案参考。国服 MuMu 与国际服 Steam PC 当前活动已有实测；日服原生窗口捕获已验证，活动识别和真正独占全屏尚未验证。PC 范围见 [PC 兼容验证](pc-compatibility.md)，分辨率与 PC 改动合并后的检查见 [桌面验收记录](desktop-acceptance.md)。

## 使用

1. 打开寻宝棋盘，运行 `ba-treasure-overlay.exe`，在控制窗选择游戏窗口并连接。
2. 默认手动模式。切回游戏，点击棋盘左侧约 40×40 的刷新按钮；也可点击控制窗的刷新按钮。它只更新助手，不点击游戏、不换轮、不消耗资源。
3. 工具读取三张卡片的尺寸、**剩余件数**与图案，再识别棋盘、计算概率。局部翻出不减件数，完整找到一件才减一。正常读取无需另行确认。
4. 翻格后再次刷新。发现物品尚未完整翻出时暂停概率，翻完后再刷新即可恢复；自动模式会继续观察并在完整识别后恢复。刷新过程中旧推荐立即失效，按钮禁用；识别或计算失败后可重试。识别最长等待 15 秒，这是失败保护时间，不是实时性能承诺。
5. 不能确认的格子显示“待确认”并停止推荐。在预览选择校正类别，再点对应格；完整灰色物品用“已完成”校正。卡片读错时可校正尺寸和剩余件数。修改后重新刷新。

概率区域点击穿透；只有小刷新按钮可点击。游戏失焦、最小化、隐藏提示或切到自动模式时，按钮隐藏。关闭控制窗即退出。手动模式空闲不读取像素、不做 OCR、不识别、不计算；因此无法自动发现你随后翻格或离开寻宝界面，需刷新或主动隐藏提示。

自动模式使用同一识别流程，以每秒最多 5 次的频率处理画面，连续两帧一致后提交；实际频率受处理耗时影响。失焦或暂停时停止提交推荐。手动和自动模式均丢弃过期计算，不堆积 Worker 队列。重复状态的预览图最多每秒更新一次；状态、几何变化及手动刷新立即更新预览。棋盘和数字仍从同一当前帧读取。

若普通识别无法处理当前方块外观，可在画面预览中点击“选择样本”，从 45 格切片里选一个或多个仍未翻开的格子（每种外观选一格即可），再保存。选择期间画面冻结并暂停推荐；取消或保存失败会保留原有样本。即使新外观不能被常规识别，只要游戏标题、三张卡片和受支持的棋盘布局仍能定位，也可提供 45 格切片供玩家挑选；这些切片在保存前只用于选择，不作为推荐依据。

手动样本保存为 32×32 像素小图，可在棋盘任意位置匹配，不按最初选择的格子位置逐格匹配。普通刷新、自动刷新、换轮、重新连接、重新校准或识别异常都不会替换它；出现不匹配时会提示检查游戏画面或更新样本。取消或保存失败时旧样本继续生效；只有玩家主动清除后才恢复自动识别。

没有手动样本时，助手仍可在剩余 45 格、三张卡片正常且没有 Finish 的开局，确认每格封闭边框并等待连续两帧稳定，再将 45 格各自外观暂存为本轮参考。自动学习的样本按原位置逐格比较，和内置参考的颜色无关。细小的新图案也会作为变化检查，不能因整体颜色相近就当作未翻格。中途接入或开局条件不足时，继续使用原有结构识别；这不代表所有活动或棋盘布局都已兼容。

自动定位支持已验证的 16:9 和国际服 PC 4:3 布局，识别工具栏、留白内的游戏内容区；4:3 的棋盘与顶部数字按居中锚点定位，物品卡片按底部锚点定位。棋盘、卡片、数字和框选使用同一布局变换。若需校正，先刷新取得预览，再拖框完整 9×5 棋盘。旧 16:9 框选配置可沿用到 4:3，仍会验证棋盘纹理，失效时提示重新框选。

窗口缩放或游戏内容区变化时立即撤下旧推荐，等待尺寸和位置连续两帧稳定后再读取。自动模式随后恢复；手动模式仍需点击一次刷新，已发起的刷新会继续等待稳定画面。仅移动窗口时提示跟随移动。同轮缩放保留已建立的物品参考，包括 Finish 物品；依赖旧像素的格子校正重新验证。

## 数字、细框与推断范围

- 未翻格显示筛选物品的命中概率，实线细框表示并列最高概率。切换筛选复用 8 组概率矩阵。
- 棋盘状态栏的“突出最高”开关默认关闭。开启后，所有并列最高概率的未翻格增加粗边框和轻微填色；控制窗与游戏叠加同步生效，偏好在本机保存。切换只重绘现有结果，不重新识别或求解。
- “精确”表示对当前约束精确枚举；“估计”使用上游 100,000 次抽样。两者都依赖输入观测正确。
- 桌面模式不再推算局部物品的位置或方向；局部命中期间不发布概率，也不显示推断范围。
- 已翻空格和完整灰色占位禁止再次放物品；恢复计算后只使用当前剩余件数和可信棋盘占位。局部翻出不扣件数。

完整物品通过灰色剪影、卡片尺寸和轮廓确认占位；桌面识别跳过局部彩色图案的角度及位置搜索。空格需要已开背景的正向证据，未匹配到物品不会直接判空。尚未确认完整的已翻区域会暂停概率，自动模式继续识别，手动模式需刷新；已翻完仍未恢复时可校正。背景或图案证据不足时允许少量人工校正，不承诺任意活动都能无干预识别。

## 换轮和中途接入

轮号连续变化，或已翻棋盘稳定恢复全盖且卡片恢复正常时，清除旧观测、参考、校正和概率，重新读取卡片。重复读取同一个全盖棋盘不会重复重置。手动模式需点击刷新后才能发现换轮。

`Finish` 不覆盖同轮已缓存的物品参考。中途接入时，正常卡片可以建立参考；已 Finish 且没有缓存的类别不会强行重建彩色图案。可可靠确认的完整灰色区域作为已完成占位；其余由用户校正。

自动学习的开局方格参考只保存在内存中，同轮调整窗口大小或短暂遮挡时保留，换轮、重新连接或重新校准时清除；只有没有手动样本时才启用。手动保存的样本跨轮次和重启保留，也不随重新连接或重新校准清除。中途连接、开局读数不全或方格边框无法确认时，不会把已经翻开的格子补学成初始参考。选中勾框、空格和完整物品仍按各自现有流程确认。

卡片校正只在当前轮、对应读数不变时生效，卡片变化后重新读取。尺寸按卡片方格的实际排列读取，不设活动特定的 4×4 上限；尺寸为正整数且任一方向能放入 9×5 棋盘即可。剩余件数每类 0–7，剩余面积合计不超过 45；无法容纳或读不到均提示处理，不截断或猜值。未来若卡片布局或图标绘制方式改变，仍需实际画面验证，不能保证自动识别。

提示会分别指出未读到的尺寸或剩余件数，并列出对应物品编号。数字裁剪统一归一化后送入本地 OCR，漏读时才补充尺度和对比度处理，冲突仍标记未知。像素确实不足时可放大窗口再刷新，或手动校正卡片；不按固定窗口分辨率承诺任意画面都能自动读取。

## 文件与环境

依赖 Windows 10/11 的 Windows Graphics Capture、WebView2 Runtime 和本地 Windows OCR。正式程序不需要 Python/Node，不调用在线 OCR，不读取或修改游戏内存，不使用渲染注入。

`%APPDATA%\local.ba.treasure.overlay\profile.json` 只保存窗口定位和更新模式。旧配置的初始数量不会被解释为剩余数量。卡片参考与校正仅保存在当前会话内。`session-diagnostics.json` 保存观测和绘制计时；`capture-diagnostics.json` 记录当前帧尺寸、内容区、几何稳定状态和失败环节，两者均不保存截图。

`%APPDATA%\local.ba.treasure.overlay\cover-reference.json` 保存玩家选中的 32×32 RGB 方格样本，在本机跨轮次和重启保留；它只包含所选小图像素，不保存完整截图，也不会上传。自动学习的 45 格本轮参考仍只保存在内存中。普通刷新、自动刷新和重新校准都不会改写手动样本。

源码在 `app/`，上级原始 `样例1.jpg` 和 MIT 许可保留。`src-tauri/tests/fixtures/` 的活动截图保留作回归资料。生产不嵌入冰面和物品碎片；仍保留通用盖子浮雕与选中勾框的结构参考，以结构相关性校验盖子，不以五种颜色决定物品身份。截图包含游戏画面，不应随意上传。

截图回放、真实 MuMu、跨活动与性能的实际验证状态见 `desktop-acceptance.md`，PC 客户端见 `pc-compatibility.md`。真实跨活动、日服活动和独占全屏不能用合成回放或 MuMu 全屏结果替代。
