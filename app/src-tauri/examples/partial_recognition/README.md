# 局部物品识别离线实验

本入口只读取截图，输出 JSON、PNG 和本地 HTML；离线报告 feature 仍需显式启用。
2026-10-08 起，桌面测试版通过默认开启的 `partial-recognition` 复用相同的匹配、
全局约束和 Δ=5 竞争逻辑，实时路径仅在内存中运行，不导出调试图。
`--inspect-image` 额外输出局部占格和求解投影，原始格子及 HUD 读数仍单独保留。
下文旧日期的“未接入桌面”指对应历史运行，不代表当前测试版。

从仓库根目录运行：

```powershell
& app/src-tauri/examples/partial_recognition/run.ps1
```

脚本使用项目已有 `.tools` Rust 环境（否则使用 PATH），构建独立 release example，先运行
调参组，保存 `freeze.json`，再使用完全相同的配置运行验证组。Node 仅汇总离线产物，
不连接任何服务。输出默认位于 `.artifacts/partial-recognition/run-时间戳/`，已有结果目录
不会被覆盖。运行期间的环境变量变更限于脚本进程并在结束时恢复。

单独运行（从仓库根目录，已配置 Rust PATH 时）：

```powershell
cargo run --manifest-path app/src-tauri/Cargo.toml --locked --release --example partial-recognition --features partial-recognition-experiment -- --manifest app/src-tauri/examples/partial_recognition/manifest.json --config app/src-tauri/examples/partial_recognition/config.json --output .artifacts/partial-recognition/my-tuning --split tuning
```

不符时拒绝执行。`--help` 提供所有参数。清单路径相对于清单所在目录。改变参数后必须
创建新的调参/冻结/验证结果，不能修改既有报告冒充先前运行。

## 样本与证据

### 最近匹配强制认定实验（2026-10-07）

在配置副本中设置 `matching.threshold_free_search=true` 可运行无分数门槛搜索。
缺省为 `false`；正常配置及桌面行为不变。实验同时绕过搜索 RGB 门槛和坏像素比例
淘汰，保留合法占格、参考图、55 个核心像素与每观测 45 个像素等有效证据要求。
每个类别/占格保存 RGB 和当前综合误差的最小值；不会用候选数量上限截断搜索。
该模式不运行原阈值/全局筛选阶段，也不导出逐位姿 PNG。

沿用上面的独立 example 命令，使用配置副本分别运行 tuning 和冻结后的 validation，
然后运行（路径均从仓库根目录算）：

```powershell
node app/src-tauri/examples/partial_recognition/evaluate-nearest.mjs <原阈值报告/results.json> <无门槛回放目录> <新对照报告目录>
```

脚本分别比较原阈值策略、原候选池直接取最近、无门槛综合分最近、无门槛 RGB 最近。
强制取最近不使用全局求解器或纹理置信门槛，完全同分时按原候选顺序选择并记录并列。
先确定预测再读取真值；漏检计入分母。真实、派生、合成正例及应保持不确定的负例
分开统计，图案角度无标注时不计算正确率。输出 `comparison.json` 和 `index.html`。
此模式应使用该专用汇总脚本，不使用正常多阶段报告的 `summarize.mjs` / `check-results.mjs`。

`manifest.json` 目前登记 34 次回放：24 张真实来源截图、6 次派生/缓存回放、4 个合成负例。

## 实现和对照

## 多占格候选的 Δ=5 分数带筛选（2026-10-08）

最终 `visible_foreground_global` 阶段可通过 `scoring.geometry_competition`
启用分数带筛选；缺省 `null` 保持原行为。原 38 分绝对门槛、候选搜索与评分均保留。
先对通过完整全局检查的候选按“类别＋占格”分组，每组取最低综合误差。
配置仅含 `error_tolerance: 5.0`，要求为有限非负数。保留最低分不高于
`最佳分 + Δ` 的全部组，只有严格超过上界才排除；至少排除一组才形成筛选提案。
同组的全部角度、缩放与偏移候选仍保留，不按候选数量投票，也不把第二个相似角度
当成另一个占格竞争者。

Δ=5 时，4/12、18/30、25/37 分别只保留前一组；11/14、35/37 保留两组。
11/14/30 保留前两组，11/16/30 也保留前两组，边界 16 分不排除。
因此无需强选单一组，最佳分较高也使用相同误差容忍范围；只有一个几何组时保持原候选。

缺失参考、证据不足、搜索或原全局检查未完成时不筛选。所有观测的筛选提案一起
重新验证完整布局，只有 `complete && Feasible` 才应用全部提案；冲突、无解、中断或
证据不足时整体恢复原候选。报告保留原全局候选、各几何组分数、最佳/次佳/分差诊断、
分数带上界、筛选提案和联合约束证据。分数带筛选不构成数学唯一性证明；保留多组时
仍按实际候选表达类别与占格待定，真实图案角度仍无验收真值。

历史回放（改用 Δ=5 前，不能作为当前规则的验证结果）：46 帧、12754 个候选的搜索、评分、原全局约束及生产输出与上一轮一致，
Direct/Tiled 46/46 一致。只有上述两部手机应用了分差筛选，TextImage 正确占格确认
从 12/14 提高到 14/14；原真实 26/26、派生 15/15、合成污染正例 1/1 保持正确，
3 个合成负例均未误确认。83 项相关测试通过。两例均保留图案角度歧义，全部同组
姿态仍可检查。结果见 `.artifacts/partial-recognition/run-20261008-geometry-competition/`
的 `index.html` 与 `comparison.json`。这仍是调参/回归，独立真实局部验证分母为 0，
未接入桌面推荐。

## 格边可见碎片的证据计数（2026-10-08）

`TextImage` 的 14 次局部观测按当前候选池最低综合误差排序均正确。两部手机仍有
竞争占格；两次冲浪板观测则因格内可靠前景仅 43 像素，未达到原有 45 像素要求。
像素核查发现 3px 格边另有 109 个可靠像素，其中至少 42 个是明显的黄橙色物体，
硬性裁掉格边遗漏了真实碎片；其余也含格框，不能全部按物体满权重计数。

现在观察证据量使用 `格内可靠像素 + low_confidence_weight × 格边可靠像素`，
沿用 `V` 的可靠前景判断和格边权重。冲浪板为 `43 + 109 × 0.1 = 53.9`，门槛仍为
45。纹理标准差继续只统计格内，避免格框对比度使纯色碎片通过；选择绿仍排除。
`reliable_foreground_pixels` 保留原格内计数，新增 `border_reliable_foreground_pixels`
和 `effective_foreground_pixels` 供诊断。模板核心像素要求、评分公式、38 分阈值、
搜索和竞争候选均不改动。

69 项测试、46 帧回放通过，12754 个候选、全部评分及各阶段保留集合前后一致。
TextImage 正确方案仍保留 14/14，确认覆盖率由 10/14 提高到 12/14，错误确认仍为 0；
原真实 26 次、派生 15 次及合成污染正例 1 次保持正确，3 个负例仍不强行确认。
两部手机的竞争占格继续保留。结果见
`.artifacts/partial-recognition/textimage-20261008-border-evidence/comparison.html`。
TextImage 已用于这次优化，后续属于调参/回归，不能再作为独立验证；先前测试报告
保持原样，独立真实局部验证缺口仍存在。此调整仍限于默认关闭的离线实验入口。

## 前景引导细化（2026-10-07）

`matching.foreground_refinement` 缺省关闭；当前实验配置显式开启。每个合法占格 /
粗角度区域额外保留一个以 `max(双向分, 实际可见前景误差)` 为目标的细化种子。
原 RGB 搜索路径、粗候选、有效像素量和坏像素门槛不变；两条路线都使用原有

时必须报告不完整。输出记录 `foreground_evaluations` / `foreground_basins`。

这修正“颜色对上一小块即可改善，而未覆盖内容到最终筛选才被发现”的搜索目标
差异。最终评分仍为 38，没有修改生产评分或将局部候选接入桌面。

## 原有匹配与约束

- `matching.rs` 是原 `vision_dynamic` 的 feature-gated 子模块，复用卡片分割、内部掩码、
  形状图标读取、旋转坐标变换、等比适配以及原 `evaluate()`。生产函数体保持原样。
- 每个合法位置、横竖占格、粗角度及 fill 都参与搜索；保留通过阈值的粗候选，按每个
  几何/角度区域细化 nuisance 参数。没有 top-K 截断。原路线沿用 RGB 目标，开启上述
  前景细化时另外探索独立路线；各组评分
  共用候选池；这不是三个独立优化器或连续位姿空间的数学穷举。
- 原评价器固有约束为 32 px/格、至少 55 个核心像素、RGB MAE >35 的像素不超过 40%。
  为复用既有函数，这些生产常量不复制为可调实验参数，其余实验参数集中于 config。
- `color = RGB MAE`；`color_edge = color + edge_weight × 内部水平/垂直梯度误差`；
  `color_edge_bidirectional = color_edge + reverse_weight × (预测内容不符比例 +
  实际可靠前景未被解释比例)`。未翻格完全排除；格边和选中绿色像素降低权重。
  可靠前景仍使用简单亮度/色差规则，其误差必须通过负例暴露。
- 每个评分分别保存视觉筛选和全局筛选。候选的 `global_feasibility` 含分阶段几何结果；
  同占格不同角度共用几何可行性，不因 solver 结果收敛而合并图案方向。
- `constraints.rs` 用 OR 连接同观测候选、AND 连接不同观测，按类别分支，共享矩形只计
  一件。固定候选后通过 `solve_snapshot_native` 查完整布局，空格、完成占位、剩余件数
  和不重叠均参与。只把经过审计的原生精确零解返回作为无解证据；抽样只提供存在见证。
- 输入错误、缺证据、计算中断、明确无解分别返回。预算只用于限制执行量，不能制造唯一。
  原生 solver 的技术边界是 9×5、3 类、每类 0..7 件；小棋盘以完成占位填充。原生调用
  没有中途取消 API，预算在调用之间检查。任何未完成的搜索都不输出确定结论。

首版参数取原搜索配置及事先声明的附加权重，没有为了验证结果调参。低纹理只影响
确定性声明，不改写观测或伪造候选。结论始终以有限候选空间为条件。

## 可见前景评分改进

手机中间碎片的错误末端候选暴露了原评分的缺口：模板核心没有覆盖到的实际物品
像素不进入主要颜色误差，双向核对虽发现遗漏，但加权后惩罚较小。`visible.rs` 因此
增加以**实际观测**为分母的前景误差，两个后端共用同一逐行计算：

- 保留原可靠前景与格边权重规则，遍历占格内所有已翻格的像素，含整个矩形的边界行列。
- 模板覆盖像素按 RGB 平均绝对误差计算；实际可靠前景没有模板覆盖时，记为 8 位 RGB
  最大误差 255。无可靠前景时返回 `null`，不能作为零误差通过。
- 新评分 `visible_foreground = max(原双向综合分, 实际前景误差)`。两侧都需要解释得通，
  不用很小的附加系数稀释缺失内容。保留纯缺失比例、颜色矛盾比例及逐格权重用于诊断。
- 初始比较保持最终阈值 38，单独引入评分改动；另设最终阈值 21、20 的对照组，沿用
  原双向评分。每组分别重算全局约束，不复用旧阈值下的几何可行性。

`matching.max_color_error` 仍是粗搜/细化候选入口的颜色门槛；`scoring` 中的最终阈值
独立配置。降低最终阈值不会抹掉细化种子。真实水枪的粗搜颜色误差 21.84，需要继续
细化才得到综合分 19.55，这个路径已纳入入口回归测试。原始三组 `scores/accepted`
保留作对照；各阶段实际决策以 `candidate_checks` 和 `observations.retained_indices`
为准，并列出筛除原因。

这仍是观测颜色与模板覆盖检查，不是语义部位识别，也未新增独立轮廓模型。可靠前景
沿用明暗/色差启发式，可能漏掉浅色物品细节；新评分不能恢复抠图或原搜索已丢失的
正确候选。本轮只在调参组比较，冻结后运行原验证组，真实局部验证分母仍为 0。

## 边缘背景污染修正与状态表达

`extraction.rs` 仅用于实验。修正位于原始前景掩码生成后、closing 之前，保持主背景
palette、RGB 原图、原形态学操作和有效性门槛。参数位于 `matching.extraction`；
配置缺省时关闭，当前实验配置显式开启，不影响生产 `extract()`。

沿用原卡片双侧采样域，附加颜色必须在左右两侧的每个纵向分段中都有足够的不同采样
行支持，才被考虑为重复边缘背景。仅移除该颜色与裁剪边界相连的原始前景组件，内部
不连到边缘的同色细部保持。没有双侧支持的触边模板保留原结果，标记 `edge_unresolved`。
这不适用于任意背景污染；真实物体若同色、双侧重复且连续触边，单卡颜色仍可能混淆。
后续截图需包含触边物体反例。没有引入后帧真值或新的参考缓存来源。

诊断记录重复颜色、移除像素、处理前后 mask 大小及是否来自 Finish 缓存。清理后无效
的模板撤销，不退回较早参考；Finish 才能保留模板，reset 清空模板及处理记录。
原 `extract()` 后半段在实验模块中按原样复用形态学和组件函数，测试检查无修正时的
掩码、核心掩码、边界、指纹精确一致；不通过改生产源码共享代码来扩大本轮范围。

报告将“类别或占格待定”与“类别、占格已确定，仅图案角度待定”分别统计，原始
`ambiguous` 字段继续保留。`direction_certain` 在界面称为图案角度收敛，不等于角度
已验证正确，缺少真值时仍为 N/A。

复现开启/关闭对照时，只修改配置副本中的 `matching.extraction.enabled`，分别运行：

```powershell

```

每次仍独立执行调参、冻结、验证。评分阈值、搜索及真值清单保持一致。

## 按占格分块的离线实现

`tiled.rs` 实现“整图变换 → 按占格切块 → 缓存 → 只匹配可见块”。先在完整占格画布
上旋转、等比缩放、留白和偏移，再切成 32×32 px 的格块；不能先切原卡再分别旋转，
否则跨格图案的位置会改变。每块保存 RGB、前景/内部掩码，并从完整画布读取相邻
像素用于边缘评分。多个露出块必须来自同一个完整位姿，不能各自选最佳角度拼接。

露出格减去模板块的局部坐标，得到候选矩形左上角。去重后的位置域与原来的合法矩形
扫描相同，仍保留所有通过原规则的候选。未知块不贡献误差，也不会被预测改写。
像素累加保持原逐行顺序，避免浮点求和顺序改变阈值或细化结果。

缓存键包括参考内容修订、占格宽高、角度、fill 和偏移的精确浮点位表示；不含棋盘
位置或验收真值。原卡内容、掩码或裁切范围变化时失效，同轮 Finish 复用已知参考，
reset 清空。`tile_cache_bytes` 默认 64 MiB，只约束缓存驻留量；淘汰或设为 0 时重新
计算模板，不截断搜索，也不限制候选数量。该预算不是整个进程的内存上限。

每次回放使用互相独立的 Direct/Tiled 会话，并交替先后顺序。`matching_direct` 保存
原逐像素匹配，`matching` 保存分块匹配，`tile_comparison` 比较候选多重集、顺序、
评分分项、证据量、观测、搜索完成状态及所有阶段决策。只有 matcher 证据完全一致时
才复用相同 solver 输入的约束证据，记录 `solver_evidence_reused`；否则单独计算。
`matching_ms` 包含缓存预处理，PNG 诊断导出另计且不能预热匹配缓存。单次回放的
时间只用于描述本次运行，不能据此承诺稳定加速。
