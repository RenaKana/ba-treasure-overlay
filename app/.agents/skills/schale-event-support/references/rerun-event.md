# 復刻イベント

復刻イベントでは過去の数量を第一候補にできるが、今回も同一であることを無条件には扱わない。

## 復刻元の特定

1. issueや告知から正式イベント名、復刻元の開催日、備品名を確認する。
2. `gh pr list`、`gh pr view`、`git log --all`、`git show` で過去PRと最終確定コミットを探す。
3. 初回の暫定PRではなく、後続PRを含めた最終値を採用候補にする。
4. 次を旧開催と今回で照合する。
   - 備品の名前と寸法
   - 各周回の備品順、数量、繰り返し周期
   - 「N周目以降」の開始位置と内容
   - 最大数量がUIと保存データ検証の範囲内か
5. 今回のスクリーンショット、issue報告、ユーザー確認と矛盾があれば、過去値より今回の証拠を優先する。判断できなければ確認する。

探索例:

```bash
gh pr list --repo terry-u16/schale-inventory-management --state merged --limit 100 --search 'イベントへの対応 in:title'
gh pr view <PR番号> --repo terry-u16/schale-inventory-management --json title,body,commits,files
git show <最終確定コミット> -- src/components/MainArea.tsx
```

## 実装と通知

- 過去イベントの備品定義が残っていれば、名前・寸法を照合して有効化する。似た寸法だけで別イベントの定義を流用しない。
- `predefinedItems` は過去の最終確定状態を基にするが、今回の周回上限やプリセット表示数へ合わせる。
- 過去値を今回も採用することが運用上の仮定なら、通知とPR本文に復刻元の開催時期を明記する。
- 全値に過去の確定根拠があり、今回の確認でも矛盾がなければ `success` にできる。今回固有の未知値を仮置きするなら新規イベントと同じく `warning` にする。
