# 新規イベント

新規イベントでは、判明している事実と仮定を混ぜず、情報が追加されたときに狭い追補で確定できる形にする。

## 情報の整理

周回ごとに次を記録する。

| 周回・範囲 | 備品1 名前/寸法/数量 | 備品2 名前/寸法/数量 | 備品3 名前/寸法/数量 | 状態・根拠                  |
| ---------- | -------------------- | -------------------- | -------------------- | --------------------------- |
| 1周目      |                      |                      |                      | 確認済み/issue/画像など     |
| N周目以降  |                      |                      |                      | 未知/ユーザー承認の仮値など |

- 寸法表記が `3x1` なら、ユーザーまたは既存コードの規約から `width=3, height=1` であることを確認する。
- 同じ備品が複数周回に出ても、備品定義は再利用し、数量と周回内indexは各プリセットで設定する。
- 周期を推定する場合、周期の起点と対象周回を展開して確認する。配列の繰り返しが正しくても、コメントを最初の推定周回の直前に置く。

## 未知値の扱い

1. まずユーザーに正しい値または採用する仮定を確認する。
2. 仮値の採用が明示された場合だけ実装する。
3. コードコメントに対象周回と「仮」を明記する。
4. 通知は「対応中」とし、確認済み・推定・未知の範囲を日本語で正確に書いてから翻訳する。
5. `NotificationPanel` を `warning` にする。
6. PR本文に仮値と情報提供依頼を記載し、必要なら `part1` とする。

確定情報が届いた追補では、値を差し替えるだけでなく、仮値コメント、4言語の通知、severity、issueのclose可否をまとめて見直す。

## 過去事例

- PR #76: 6周目までを反映し、7周目以降を各1個の仮値としてwarning表示にした。
- PR #79: 7周目の確定値を反映し、仮値コメントを削除してsuccessへ戻した。
- PR #83、#85、#86: 1周目のみ判明した状態から段階的に数量と通知を更新した。
- PR #109: 7〜12周目を周期推定、13周目以降を明示承認された仮値として、13プリセットと4言語表示を揃えた。

過去の仮値そのものは再利用しない。再利用するのは、不確実性の表示と段階的な確定方法だけである。
